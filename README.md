### 🤖 JIRA-AI — 이슈 자동 분석·업무 자동화 AI 시스템 (1인 개발 · 운영중)
- **기간** : 2026.04 ~ 현재 (고도화 진행 중)
- **기술스택** : Java 17, Spring Boot 3, LangGraph4j, Spring AI, Azure OpenAI, MCP, Kafka, Redis, MariaDB/Flyway, React 18, TypeScript
- **담당 역할** : 기획, 설계, 개발 단독 수행. AI 코딩 도구 사용 사실은 커밋 공동 저자로 기록
- **한 일** :
  - "쌓여 있는 방대한 Jira 데이터가 있는데, 왜 같은 문의에 매번 사람이 답하는가"라는 문제의식에서 출발. 문의 이슈 등록 시 사내 지식·GitLab 소스·유사 이슈를 대조해 근거가 붙은 1차 답변 생성
  - 단일 LLM 호출 구조를 **LangGraph4j 15노드 워크플로**로 확장 — 근거 부족 시 재수집, 검수 FAIL 시 재합성. 유사 이슈 조회는 LLM 자율 선택 시 누락이 발생해 결정적 단계로 분리
  - GitLab 소스를 상한 내에서 읽어 **RAG 코드 인덱스** 생성 — LLM이 고른 파일 경로는 원본 후보 집합으로 재검증
  - 담당자 답변을 `_pending` 폴더에 격리해 관리자 승인 이동 후에만 검색 반영. 실패 분석은 **Kafka DLT**에 보존 후 60분 지연 재접수
  - permit-all API를 **JWT 역할 규칙**으로 전환하고 401·403·200을 테스트로 고정. 동시 401 시 refresh token 이중 소비 경쟁 조건 해소
  - 메일 도메인 구축 요청을 접수 → **담당자 승인** → 예약 재검증 → A10/WBlock 등록 → 보상 → 수동검토 상태로 관리. webhook actor를 신뢰하지 않고 Jira 재조회로 실제 담당자 확인
- **미측정 항목** : 답변 정확도 개선폭, 담당자 처리시간 단축
